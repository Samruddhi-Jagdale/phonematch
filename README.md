# PhoneMatch: an explainable smartphone recommender (classical ML only)

PhoneMatch ranks phones for a buyer by combining three signals:

1. **Specs**: five 0-100 scores (performance, camera, battery, display, value) built from raw specifications.
2. **Owner reviews**: a TF-IDF + logistic regression sentiment classifier scores every review sentence, and sentences are
   grouped by the aspect they mention (battery, camera, ...). *(Feature 2)*
3. **Fair price**: a gradient-boosting model predicts what a phone should cost from its specs. The gap between that and the real
   price is the value score, and an occlusion-style explanation shows how each spec moves the price. *(Feature 3)*

Phones are also segmented into market tiers and the clustering is validated across three algorithms and three metrics. *(Feature 5)*
Only classical machine learning is used: no deep learning.

> **Dataset: the bundled data is synthetic** (fictional brands, simulated specs, prices and reviews, generated by
> `generate_data.py`). See `DATASET.md`. Use `prepare_real_data.py` to switch to a real dataset.

## Method summary
- **Value model.** Predict log price from 11 specs. Four regressors are compared with 5-fold CV (R², MAE, MAPE). Gradient boosting is
  tuned with grid search. Out-of-fold predictions give `value_gap = (predicted - actual) / predicted`. Ablation (drop one feature
  group) and permutation importance are reported.
- **Sentiment.** 4-5 stars = positive, 1-2 = negative, 3 dropped. Logistic regression, Naive Bayes and linear SVM are compared (5-fold).
  Per-phone aspect scores are shrunk toward the catalogue mean when there are few mentions.
- **Clustering.** K-Means, Ward hierarchical and Gaussian mixture, k = 2 to 8, with silhouette, Davies-Bouldin and Calinski-Harabasz.
  The app uses K-Means with the best silhouette in k = 3 to 6, projected with PCA.
- **Recommender.** `match = sum_d w_d * ((1 - t) * spec_d + t * review_d)`, with user weights `w` (normalised) and review trust `t`.
  Every term is shown in the UI, so each recommendation is explainable. "Similar phones" uses cosine similarity on standardised specs.
- **Evaluation without ratings.** There are no per-user ratings, so the recommender is evaluated on six simulated buyer personas with
  proxy metrics (store rating, value gap, spec fit, review fit, brand diversity). State this limitation in your report.

## Deploy
**Streamlit Community Cloud (free, easiest)**
1. Create a GitHub repository and push the project folder (keep `data/` and `results/`).
2. Go to share.streamlit.io, sign in with GitHub, choose *Create app*, select the repo and branch, and set the main file to `app.py`.
3. Under *Advanced settings* pick Python 3.11, then *Deploy*. The first launch trains the models (a few seconds).

**Hugging Face Spaces (free)**: create a Space with the *Streamlit* SDK, upload the files, and add this header at the top of `README.md`:
```
---
title: PhoneMatch
sdk: streamlit
app_file: app.py
---
```
**Docker (any host)**: `docker build -t phonematch .` then `docker run -p 8501:8501 phonematch`.

## Switching to real data
1. Edit `COLUMN_MAP` in `prepare_real_data.py`, then `python prepare_real_data.py your_file.csv --source "Kaggle: dataset name"`.
2. Put real reviews in `data/reviews.csv` (`phone_id, stars, text`), or run `python generate_data.py --reviews-only` for simulated ones.
3. `python run_experiments.py`, then `pytest -q`, then restart the app. The "demo data" banner disappears when `dataset_info.json` says `real`.

## Limitations
- Bundled data is synthetic, so metrics measure how well methods recover simulated patterns, not real-world performance.
- No real user ratings: recommender evaluation uses personas and proxy metrics.
- Sentiment is trained on review-level stars and applied to sentences, which is an approximation.
- Specs do not capture software, build quality or after-sales service; prices change quickly.

## Possible extensions
Pairwise preference survey to learn the weights, time-based validation on real launch dates, price tracking, and a real review scraper.
